# ربات تخمین رتبه آکادمی الف

ربات تلگرام آکادمی الف برای تخمین رتبه کنکور، تراز معدل نهایی، ترکیب درصد و معدل، و تحلیل تراز آزمون‌های آزمایشی است. این نسخه با JavaScript روی Vercel Functions اجرا می‌شود، از webhook تلگرام استفاده می‌کند و وضعیت کاربران را در PostgreSQL نگه می‌دارد.

## قابلیت‌ها

- تخمین رتبه رشته‌های تجربی و ریاضی بر اساس تراز و منطقه
- نمایش سه پیشنهاد رشته‌محل ثابت برای هر منطقه و بازه رتبه با داده‌های استخراج‌شده از فایل‌های قبولی تجربی، ریاضی و انسانی
- تخمین مستقیم قبولی با ورود رتبه برای گروه‌های تجربی، ریاضی و انسانی
- تخمین بازه تراز از معدل کل یا نمره‌های تک‌درس
- تخمین رتبه از ترکیب ۶۰٪ معدل و ۴۰٪ درصدهای کنکور
- دریافت یک‌باره شماره کاربر پیش از نمایش نتیجه
- ذخیره دائمی تمام شماره‌های Shareشده در جدول مستقل مخاطبین
- ثبت مستقیم درخواست مشاوره رایگان با شماره تماس و آخرین نتیجه
- نمایش فهرست درخواست‌های مشاوره برای مدیران با دستور `/moshavereha`
- نمایش و ارسال تمام Contactهای ثبت‌شده برای مدیران با دستور `/contact`
- نمایش دکمه‌های مدیریت فقط برای حساب‌های تعریف‌شده در `CONTACT_ADMIN_CHAT_IDS`
- هدایت کاربر از نتیجه تخمین تراز نهایی یا آزمون به بخش تبدیل تراز به رتبه
- نگهداری دائمی state و تأیید شماره در PostgreSQL
- اجرای serverless با webhook و بدون worker همیشه‌روشن
- ارسال تصاویر و محتوای ثابت آکادمی
- ارسال تصویر رتبه‌های برتر بدون کپشن متنی

## معماری

تلگرام درخواست‌ها را به `api/webhook.js` می‌فرستد. درخواست با secret اختصاصی اعتبارسنجی می‌شود، update تکراری کنار گذاشته می‌شود، state کاربر از PostgreSQL خوانده می‌شود و بعد از پاسخ ذخیره می‌گردد. endpoint ریشه و `api/health.js` برای health check در دسترس‌اند.

## اجرای محلی

Node.js نسخه 20 یا جدیدتر و یک دیتابیس PostgreSQL لازم است.

```bash
npm install
cp .env.example .env
npm test
npm run check
```

مقادیر `.env` را کامل کنید. برای دریافت update واقعی در محیط محلی باید یک URL عمومی HTTPS در اختیار تلگرام قرار گیرد.

## متغیرهای محیطی

| نام | کاربرد |
| --- | --- |
| `BOT_TOKEN` | توکن ربات از BotFather |
| `DATABASE_URL` | رشته اتصال PostgreSQL سازگار با Neon |
| `TELEGRAM_WEBHOOK_SECRET` | secret تصادفی برای اعتبارسنجی درخواست‌های تلگرام |
| `CONTACT_ADMIN_CHAT_IDS` | شناسه مدیران با جداکننده ویرگول |
| `PUBLIC_BASE_URL` | آدرس production پروژه Vercel بدون اسلش انتهایی |

فایل `.env` در Git نادیده گرفته می‌شود و نباید commit شود.

## استقرار روی Vercel

1. ریپو را به یک پروژه Vercel متصل کنید.
2. از Marketplace یک دیتابیس Neon PostgreSQL بسازید و آن را به پروژه متصل کنید.
3. متغیرهای محیطی جدول بالا را برای Production تنظیم کنید.
4. پروژه را deploy کنید.
5. آدرس production را در `PUBLIC_BASE_URL` قرار دهید و دوباره deploy کنید.
6. webhook و commandهای ربات را ثبت کنید:

```bash
npm run webhook:set
```

جدول‌های `bot_users`، `telegram_updates`، `consultation_requests`، `contacts` و جدول‌های ارجاع در اولین درخواست به‌صورت خودکار ساخته می‌شوند. شماره‌های موجود قبلی نیز هنگام ایجاد جدول مخاطبین به آن منتقل می‌شوند. فایل‌های migration در پوشه `migrations` نگهداری می‌شوند.

مدیران می‌توانند با دستور `/referral` یک لینک ارجاع بسازند؛ برای نام‌گذاری جداگانه از `/referral channel-name` استفاده کنید. دستور `/referrals` شمارش تجمیعی را در ربات نشان می‌دهد. فایل اکسل شامل آمار هر کد و شمارش روزانه را با `npm run report:referrals` می‌سازد. برای جلوگیری از شمارش تکراری، شناسه تلگرام با HMAC به یک کلید ناشناس تبدیل می‌شود؛ نام، شماره یا شناسه تلگرام وارد جدول ارجاع و گزارش اکسل نمی‌شود. هر کاربر برای هر کد ارجاع فقط یک‌بار شمرده می‌شود.

## جریان مشاوره

پس از نمایش هر نتیجه، ربات مزایای مشاوره رایگان و دستور `/data` را معرفی می‌کند. این دستور در صورت نیاز شماره متعلق به خود کاربر را دریافت می‌کند و درخواست را بدون فرم اضافه ثبت می‌کند. هر کاربر فقط یک درخواست می‌تواند ثبت کند. ادمین‌ها یک کارت Contact و خلاصه رشته، منطقه، تراز و رتبه را فقط در اولین ثبت دریافت می‌کنند.

پیشنهادهای تقریبی قبولی فقط بعد از محاسبه‌ای نمایش داده می‌شوند که نتیجه رتبه داشته باشد. ضرایب معدل نهایی و درصدهای کنکور فقط در محاسبات داخلی استفاده می‌شوند و به کاربر نمایش داده نمی‌شوند.

مدیران می‌توانند با دستور `/moshavereha` تعداد کل و فهرست همه درخواست‌ها را مشاهده کنند. این دستور برای کاربران عادی قابل استفاده نیست.

## دسترسی مدیران

دکمه‌های «فرم‌های مشاوره» و «مخاطبین» فقط در منوی دو حساب موجود در `CONTACT_ADMIN_CHAT_IDS` نمایش داده می‌شوند. دستورهای `/moshavereha` و `/contact` نیز در سمت سرور دوباره کنترل می‌شوند و برای سایر کاربران اجرا نخواهند شد. دستور `/contact` ابتدا تعداد کل را نشان می‌دهد و سپس کارت Contact و مشخصات ثبت هر مخاطب را ارسال می‌کند.
